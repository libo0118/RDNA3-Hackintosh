A. Open findings from the card (first)

  1. macOS monitor name ("Unknown") [card] - fb/rdna3-fb.cpp. 1b38786 logs what IOGraphics asks (HLDDC sense, hasDDCConnect) and what the core answers (displayEdid), and retries the EDID fetch. Next run decides between: IOGraphics never asks (then set kConnectionSupportsHLDDCSense from start(), publish IODisplayEDID on the IODisplayConnect ourselves, or answer getDDCBlock with the right block numbering) and the core refusing (fix displayEdid).
  2. Head -> connector routing [sim] - hw/dcn32.c, kext/src/RDNA3Display.cpp. Today head 0 takes "the EDID that contains its mode". Port the read-back amdgpu uses for seamless boot: optc1_get_otg_active_size / dcn10_get_dig_frontend (DIG_FE_CNTL.DIG_SOURCE_SELECT = OTG), dcn10_get_dig_mode, DIG_BE_CNTL.DIG_FE_SOURCE_SELECT, and the transmitter (UNIPHY A-G) -> VBIOS path -> DDC line. Publish RDNA3,Head<n>,Connector. Simulator: GOP state with OTG1 -> DIG2 -> UNIPHYB.
  3. DMCUB (step 5b) [card] - hw/dmub32.c. CW0/CW1 are zero when we start the PSP-loaded DMCUB. Pending test rdna3lvl=5 rdna3dmub=1 rdna3pm=0. If still zero: compare with dm_dmub_hw_init + dmub_srv_hw_init for DMUB_WINDOW_0_INST_CONST when load_type == PSP (amdgpu passes the inst_const region anyway and programs CW0 itself only when !psp_loaded?) - re-read dmub_dcn32_backdoor_load vs dmub_dcn32_setup_windows, try the backdoor load (rdna3dmub=2) as the fallback already in the code.
  4. Refresh rate read-back [sim] - one run printed 63.741 Hz for a 1080p60 head. optc1_get_hw_timing + DCCG OTG_PIXEL_RATE/DTO read: check dcn32_head_refresh against dccg32_get_pixel_rate_div (OTG_PIXEL_RATE_DIV, DTBCLK vs DPREFCLK).

B. Display: our own mode setting (light the second monitor) [big]

Goal: HDMI/TMDS SST on DCN 3.2 (both monitors here are TMDS; DP later), second head, mode change from macOS. Plan B of the old plan: a mini-DC, not the whole amd/display/dc.

B1. Register read-back and model [sim] - generate DIG FE/BE, HDMI stream encoder, DCCG (OTG_PIXEL_RATE_CNTL, DPPCLK_DTO, PHYASYMCLK), OPP/MPC (MPCC_*, OPP_PIPE_CONTROL) headers with tools/gen_regs.py; simulator gets a DCN pipe model (HUBP -> DPP -> MPC -> OPP -> OTG -> DIG -> PHY) that knows what "lit" means. B2. Timing + scanout on a free pipe [sim] - optc1_program_timing (done in dcn32_mode.c as values) applied: optc32_enable_crtc, optc1_program_global_sync, hubp2_program_surface_config / hubp1_program_pixel_format, dpp bypass, MPCC tree for one plane, opp_program_fmt (8 bpc, no dither). Same order as dcn20_enable_stream_timing + dcn20_program_pipe. B3. Pixel clock [sim] - DCN 3.2 drives the OTG pixel rate through DCCG DTO (dccg32_set_dtbclk_dto / dccg2_set_dpp_clk), the PHY symbol clock through the VBIOS SetPixelClock (v7) - run it with our ATOM interpreter (hw/atom.c), or through DMCUB (dmub_cmd SET_PIXEL_CLOCK) once 5b works. B4. Encoder + transmitter [sim, card] - DIGxEncoderControl (v5, ENCODER_CMD_STREAM_SETUP HDMI) and DIG1TransmitterControl (v1.7, TRANSMITTER_CONTROL_ENABLE) through the ATOM interpreter (amdgpu's bios_parser2 command tables), enc32_stream_encoder_hdmi_set_stream_attribute (AVI infoframe off at first), dcn32_unblank_stream. B5. Bandwidth [sim] - minimum: request DISPCLK/DPPCLK from the SMU (smu_v13_0_set_hard_min_clk), fixed watermarks/DLG from a 1080p60 table (DML later); dcn32_prepare_bandwidth subset. B6. Framebuffer [card] - RDNA3Framebuffer: one instance per head, getDisplayModeCount/getDisplayModes from the EDID's usable modes, setDisplayMode -> core modeset call (RD3K_DISPLAY_FN_MODESET), IOFBConnectInterrupt on HPD. B7. HPD interrupts [sim] - DCN HPD IH sources (DC_HPD1_INT..), dce110_hpd_irq enable/ack, re-probe EDID on change, notify the fb.

Ladder: new step 9b = second monitor lit by us, 9c = mode change.
