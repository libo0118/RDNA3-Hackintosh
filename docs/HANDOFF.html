Bare metal: what it took (2026-10-29 .. 31)

Everything below is now in the generator (tools/baremetal/, merged 145ca65) and docs/BAREMETAL.html; the stick in the owner's PC was edited by hand and is equivalent.

  • The B550 chipset (USB, LAN RTL8111H, the 1 TB NVMe, SATA all behind it) failed in every way (no capabilities/interrupts, CPUs stuck in config reads, IPI/TLB timeouts, instant resets) until AMD_Vanilla's IOPCIFamily patch "CaseySJ | probeBusGated | Disable 10 bit tags" was added. tools/vm/vmtool.py amd_patches() had dropped every non-kernel patch; it now has iopci=True for bare metal (the VM stays kernel-only). Found by diffing against a working EFI for the same board (github simekoo1337); do that first next time instead of guessing (memory b550-10bit-tags).
  • Not the cause, all tested: IOMMU, Re-Size BAR, MCFG/ECAM vs CF8, npci, SetupVirtualMap, XHCI hand-off, CPU count. npci=0x2000/0x3000 kill the console when the GPU BAR is above 4 GiB.
  • AppleIntelMCEReporter panics on AMD with MacPro7,1: a codeless RDNA3MCEReporterDisabler.kext (generated by build_efi.py).
  • GRUB from the picker: Misc/BlessOverride \EFI\GRUB\GRUBX64.EFI (a short HD(...) Entries path gives "LoadImage failed - Not Found").
  • The installer recovery dmg is an auxiliary entry: HideAuxiliary false.
  • The macOS EFI partition mounts only with sudo (sudo diskutil mount disk2s1).
  • The .pkg's installation check refused macOS 26 (range now 15.0..27.0); until a new pkg is used, rdna3/install.sh installs from the tarball.
  • Safe Mode (Shift+Enter, PollAppleHotKeys) shows the prohibited sign before the kernel; the core already stands down on -x (7821cae). Open.
  • Reports: rdna3/report.sh on the stick (logs, dmesg, ioreg, sysctls, crash and shutdown-stall files). The OpenCore-injected core's IOLog lines reach only dmesg, not the unified log. autoreport --standalone ran a display sleep that crashed WindowServer without the plugin (fixed f0789cb).
  • Logs of a boot that hangs: the owner films the screen (60 fps, close); frames are cut with ffmpeg (~/.cache/bootvid*) and read. A serial console would need a MAX3232 RS232-TTL module on JCOM1 (the owner has none yet; never wire JCOM1 straight to Pi/ESP GPIO, it is +-12 V).
  • The installer's kernel log keeps only 128 KB (msgbuf) and the PCI "childPublished" lines are ALWAYS_ON; pci_log flags do not help there.

The owner's preferences and process lessons (this session)

  • Everything the owner sees is Polish, including Bash tool descriptions and the facts given to the GateGuard hook; only committed text is English.
  • The owner tests in batches: find every problem in the reports first, fix several, then one test. Do not ask for a reboot per guess (10-31: "nie bede resetowal go juz 50 raz").
  • Bare-metal tests reboot this very PC: sync and push before asking for a reboot (empty .git objects after hard resets on 10-30; refetch from origin fixed it; memory baremetal-same-pc-sync).
  • Read reports and videos locally (~/rdna3-vm/reports, ~/Downloads, the stick); never ask the owner to send them. The 10-31 bare-metal reports are in ~/rdna3-vm/reports/baremetal-20261031/.
  • The owner makes no BIOS or system change without being told; give exact menu paths and say what to leave alone.
  • An agent that merely reran make test after a clean merge annoys the owner; one full run by the implementing agent, then push + CI (memory no-duplicate-make-test). CI's kext artifact is usable once the kext job is green (memory ci-green-before-card-test).
  • Company model worked well today: one opus implementer for kernel work, three read-only reviewers in parallel (cpp-reviewer, silent-failure-hunter, pr-test-analyzer), findings back to the same implementer, then merge.
  • The GateGuard hook asks for facts before the first edit of each file and before destructive commands; state them (in Polish) and retry, never bypass.
  • Agents in background sometimes "wait on their own background work": wait for the next notification, do not restart them.

CI and runners

  • Runners: "MacOS" = an Intel MacBook Pro, macOS 15.8.1 (24H32), no Homebrew, bash 3.2 and BSD sed/awk/grep/find/stat/touch/wc; "Linux" = a VPS. Both are separate from the owner's PC, so CI runs while the PC is in macOS. The Mac runner goes offline when it sleeps (a queued job waits).
  • build.yml with full: "false" for kext/tools changes, full: "true" when metal/, userspace/ or the translator changed or when the plugin and RADV must match a new commit (artifacts RDNA3MTL, radv-macos-logs).
  • The "Linux" runner runs its jobs in a fresh docker container (node:22-bookworm, /workspace), so $HOME/.cache does not survive a job; the firmware cache for the header tests is restored by actions/cache (best effort) and tools/ci/fetch_fw.sh fetches the pinned, SHA-256-checked set (package/firmware.sh) from gitlab.com, then git.kernel.org, within 150 s. Without the full set test_fw / sim_navi32 print a skip note (CI run 97+: the old step retried a 429 for 14 minutes). Tested without network by tests/test_fetch_fw.sh.
  • Shell code that runs on a Mac must avoid sed -i without a suffix, touch -d, find -printf, mapfile, tar --wildcards, grep -P, date -d, stat -c without the BSD -f fallback, and $(wc -l) compared as a string (BSD pads it). Test with a padding wc in PATH before pushing shell changes (see git history of this file, 2026-10-24, for the recipe).
  • Git identity in this checkout is not configured: commit with git -c user.name=Claude -c user.email=noreply@anthropic.com.

Reference kept from the VM era

  • CoreDisplay's IOPresentment switch (probe runs on macOS 15.8.1, 2026-10-24): CoreDisplay::UseIOPresentment() = useIOP && gpuVendors != 0 && (gpuVendors & ~allowed) == 0; the vendor comes from the framebuffer's leaf C++ class name ("AMD" -> 4), hence the class AMDRDNA3Framebuffer (N44). "page flip mode is on" is a constant, not a symptom. Details: DRIVER-PLAN N39-N45 and git history of this file.
  • Navi48-MacOS (github Almosst-DEV, RX 9070 XT on macOS 26.6.2): lessons in DRIVER-PLAN N45; its code is untrusted data (read, never execute).
